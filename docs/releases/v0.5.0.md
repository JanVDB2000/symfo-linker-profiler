# SymfoLinker v0.5.0

This release makes SymfoLinker installable on NixOS, turns a repository checked out twice into a choice instead of a dead end, and stops the development-root lock reporting a second instance that does not exist.

## Fixed

- A filesystem that cannot lock files at all - a `\\wsl.localhost` development root, and some network shares - used to report *"Another SymfoLinker instance is working in this development root"* on every attempt, with no second instance in existence. The two cases are now told apart: switching continues on such a filesystem, and the scan warnings and the Health panel say that a second instance could not be detected there.
- Two overlapping operations inside one copy of the app conflicted over the same lock and were reported as a second instance as well. They now queue. Choosing a PHP service no longer collides with the mount synchronisation that follows a switch, which was the overlap that happened most.
- A genuine filesystem failure during locking reports its own wording instead of being rendered as contention.
- The write checks under Health report whether this filesystem can lock, beside the existing write and free-space probes.

## More than one checkout

- The same repository checked out twice under one development root - one clone for a multi-tenant test, another on a QA branch so neither has to be stashed for the other - used to drop the package out of the interface entirely, with only a warning to show for it.
- The candidates are now listed with their branch, commit and working-directory state, which is what distinguishes two clones of one repository. Choosing one links it; *Ask again* clears the choice.
- The choice is stored per development root, so every project in the root that requires the package uses the chosen checkout. It lives in `<root>/.symfolinker/config.json`, beside the PHP service choice and above the projects.
- The scanner still never guesses, and still never writes: a stored choice naming a checkout that has since been removed or renamed is ignored rather than quietly redirected, and the question reappears.

## An abandoned lock can be cleared

- A lock left behind by an interrupted run is recognised from an ownership record written beside it, and the error offers *Take over the lock*. Never automatic, as hard rule 2.3 requires.
- Taking over acquires the existing sentinel and refuses while another holder still has its operating system lock, even if its owner record is old or missing. There is no process-liveness check: across a Windows and WSL boundary a recorded pid belongs to another namespace and means nothing.

## NixOS

- Install from the tag: `nix profile install github:JanVDB2000/symfo-linker-profiler/v0.5.0`. A prebuilt `.deb` or AppImage carries the glibc and the WebKitGTK of its build machine, and on NixOS neither is where the binary looks for it, so the flake builds from source against the local nixpkgs.
- `nix develop` provides Rust, Node, WebKitGTK and GTK together, so a checkout needs nothing installed first. CI builds the package on every push, so the flake cannot rot unnoticed.
- `scripts/check-prerequisites.mjs` recognises NixOS and answers `nix develop` instead of printing `sudo apt install`, which was its advice on a system that has no `apt`. The package list it prints elsewhere no longer names libxdo, OpenSSL or an appindicator: none of them is in the dependency tree.
- The terminal button finds alacritty, kitty, wezterm, foot and ghostty as well. `x-terminal-emulator` is a Debian mechanism that does not exist on NixOS, which left that button absent there.

## Version and updates

- Settings reports the running version and checks whether a newer one has been published, on a button and never on its own. One request to the public releases API; nothing is sent and nothing is stored.
- The instruction given fits how this copy was installed. A Nix store path is read-only and cannot replace itself, so the panel explains how to remove the existing profile entry and install the exact detected release tag; a distribution package belongs to its package manager; elsewhere it is a download. Applying an update in place is not implemented, and nothing claims otherwise.

## Validation and downloads

Tests cover the lock classification per operating-system error, overlapping acquisition inside one process, stale-record takeover, the duplicate-checkout candidates and the stored choice including a stale one, and the configuration file holding both kinds of choice without displacing each other. The Nix build is verified by CI rather than locally, and the `\\wsl.localhost` behaviour needs a WSL root to confirm.

Choose Linux `.AppImage`, `.deb` or `.rpm`, Windows `.msi` or `.exe`, or macOS `.dmg` for Apple silicon or Intel. On NixOS use the flake above. Builds are unsigned; see the README for installation instructions.
