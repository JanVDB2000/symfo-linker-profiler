# SymfoLinker v0.3.0

This release fixes linking after a Composer reinstall and adds missing local dependency mounts to a running Docker Compose PHP service.

## Fixed

- A failed package switch keeps the workspace and selection visible and refreshes package states automatically. If refreshing also fails, the visible state is marked stale and further switches require a successful refresh.
- Relinking after Composer replaces a symlink with a new vendor directory archives the older backup and preserves the newly installed version as the current backup. Returning to VENDOR restores that current version.
- Manual Sync rereads package states after Composer changes.

## Docker mounts

- Runtime inspects actual bind mounts and shows the exact missing source mounts needed by relative vendor symlinks.
- A confirmation previews the mounts before recreating only the selected PHP service. Other services are not recreated.
- Original Compose files, project name and custom environment files are retained. Additional mounts live in a generated override under the development root.
- Docker requires service recreation to add bind mounts. Mounted data is reused; changes stored only in the container's writable layer are lost during recreation.
- Future Compose commands must include the generated override to retain the additional mounts. Automatic application requires verifiable Docker Compose labels.

## Validation and downloads

Regression tests cover Composer reinstall, backup rollback, workspace retention, mount destinations and Compose command construction. Live Docker execution was not tested locally.

Choose Linux `.AppImage`, `.deb` or `.rpm`, Windows `.msi` or `.exe`, or macOS `.dmg` for Apple silicon or Intel. Builds are unsigned; see the README for installation instructions.
